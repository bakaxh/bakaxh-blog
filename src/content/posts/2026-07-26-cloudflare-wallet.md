2026 年 8 月 4 日，Cloudflare 官方博客发布了题为《Announcing Cloudflare Wallets: the programmable wallet for the agentic Internet》的公告，正式推出 Cloudflare 钱包服务。

**地址**：[https://cloudflare.pay/](https://cloudflare.pay/)  

---

## 一、AI 代理在现有支付体系中的困境

目前，Agent在尝试调用第三方 API 时，普遍面临以下障碍：

1. **身份缺失**：代理没有独立的、可被服务商识别的稳定标识，无法完成注册或登录流程，这些流程通常针对人类用户设计（如验证码、2FA多因素认证）。
2. **支付能力缺失**：代理缺乏原生支付手段。传统的支付方式（信用卡、账单）需要人工介入绑定和确认，代理无法自主完成支付动作。
3. **流程断裂**：上述缺失导致代理在调用新 API 时，必须将注册、计费、密钥获取等环节转交给人处理，极大降低了自动化和探索效率，也阻碍了“代理经济”（agentic commerce）的形成。

Cloudflare 认为，随着互联网流量中机器人占比持续上升，为代理提供一等公民身份和支付工具已成为基础设施层面的必要演进。

---

## 二、解决方案

Cloudflare 钱包并非单一的支付工具，而是一个包含身份、支付、授权三层能力的系统。其核心组件如下：

### 2.1 账户钱包（Account Wallet）

- **归属**：Cloudflare 账户的人类所有者。
- **功能**：存储稳定币（如 USDC），管理总资产，设定全局预算。
- **权限**：可向虚拟钱包注资、调整限额、提现，是人类对资金进行最终控制的入口。

### 2.2 虚拟钱包（Virtual Wallet）

- **归属**：AI 代理或应用。
- **认证方式**：通过 API 密钥操作，无需人类交互。
- **消费约束**：由账户钱包所有者设定三项护栏：
  - **预算上限**：虚拟钱包可使用的总金额。
  - **允许列表**：可调用的服务商白名单。
  - **单笔交易上限**：单次支付的最高额度。
- **意义**：在赋予代理自主权的同时，通过硬性限制控制风险，避免超支或滥用。

### 2.3 `cloudflare.pay` 句柄（身份标识）

- **形式**：人类可读的域名式标识，例如 `research.example.cloudflare.pay`。
- **作用**：将代理的密钥对（技术上不可读）映射为类似 DNS 的可读名称，便于商户识别代理的来源组织。
- **可选性**：代理可自愿选择是否在交易中声明该身份，商户也可自行决定是否优先与已声明身份的代理交易。

支付层采用 **x402 协议**，将微支付直接嵌入 HTTP 请求头，实现按次计费（如每次 API 调用扣费几分钱），无需跳转登录页面或单独生成账单。

## 三、设计亮点分析

### 3.1 分层授权与风险隔离

账户钱包与虚拟钱包的分离，实现了“人类掌控全局，代理自主执行”的平衡。人类只需设定总预算和规则，代理在规则内自由探索，既减少了人工干预频次，又将潜在损失锁定在预算额度内，是一种兼具效率与安全的设计。

### 3.2 身份归因解决信任难题

以往，商户无法区分匿名机器人的访问来源，难以给予差异化待遇（如免费试用额度）。`cloudflare.pay` 句柄为代理提供了可验证的组织归属，使商户能够基于组织信誉建立信任机制，从而促进双边市场的形成。

### 3.3 微支付降低采用门槛

x402 协议与稳定币微支付的结合，使得单次 API 调用的成本极低（几美分），且无需预付月费或签订合同。这极大降低了代理“试错”的经济成本，鼓励大规模横向对比和动态选择服务商。

## 四、潜在挑战与待观察问题

尽管框架设计完整，但从实际落地角度，仍存在不小的挑战：

1. **稳定币合规与波动**：稳定币（如 USDC）虽锚定法币，但在不同司法管辖区的监管政策尚未统一，出入金流程可能受阻。此外，即便波动较小，企业财务部门仍可能对持有加密资产持谨慎态度。

2. **x402 协议生态的普及**：该支付方式的效用高度依赖服务商是否主动接入。目前仅 Cloudflare 的 Monetization Gateway 原生支持，若缺乏广泛的 API 生态支持，钱包的实际使用场景将受限。

3. **代理安全风险**：即使设有预算上限，代理仍可能因提示注入（prompt injection）或其他攻击而被诱导执行非预期的支付操作，耗尽额度。这要求虚拟钱包的策略配置需结合行为检测等额外安全层。

4. **身份声明与隐私的平衡**：`cloudflare.pay` 虽提供归因能力，但强制或过度依赖身份声明可能削弱代理的匿名性，需确保声明完全可选，且商户不能因此歧视未声明者。

---

## 五、结语

Cloudflare 钱包的公告，标志着主流云服务商首次系统性地将 AI 代理视为独立经济主体，并为它们配备原生支付与身份基础设施。这一方向顺应了自动化交易增长的趋势，有望重塑 API 经济的交互模式。

其最终成效取决于生态协同、监管演进和安全机制的完善。对于开发者与 API 提供者而言，密切关注 x402 协议和 Cloudflare 钱包的后续落地进展，将有助于提前布局代理经济时代的接入策略。
